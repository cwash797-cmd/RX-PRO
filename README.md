# RX-PRO

Android-клиент для панели [Panel-Naive-Mieru-by-RIXXX](https://github.com/cwash797-cmd/Panel-Naive-Mieru-by-RIXXX).

## RX-PRO Windows 0.1.0 — S3 portable

Отдельный Windows-клиент для S3-ссылок [RX-PRO S3 Manager](https://github.com/cwash797-cmd/RX-PRO-S3-Manager).
Android остаётся на версии **1.6.0**, его APK, пакет и подпись не меняются.
Windows-выпуски имеют отдельные теги `windows-v…`; не путайте ZIP Windows с Android APK.

### Начало работы

1. Скачайте **RX-PRO-Windows-0.1.0-x64.zip** из [Windows-релиза 0.1.0](https://github.com/cwash797-cmd/RX-PRO/releases/tag/windows-v0.1.0)
   и сверьте SHA256 с файлом `SHA256SUMS.txt` этого выпуска.
2. Распакуйте **весь ZIP** в отдельную папку. Запускайте `RX-PRO Windows.exe`, а не ядро
   из `core`. Устанавливать .NET отдельно и запускать от администратора не требуется.
3. Добавьте пользовательскую S3-ссылку менеджера. Обычная VLESS-ссылка панели не подойдёт.
4. Выберите профиль. Для Chrome/Edge включите «Использовать системный прокси Windows»
   и подтвердите временную замену настроек. В ручном режиме используйте локальные HTTP/SOCKS5
   адреса и порты из окна приложения. Порты выбираются заново при подключении.
5. Нажмите «Подключить», затем «Проверить через прокси». Готовность локального порта
   сама по себе не подтверждает доступность VK и вашего VPS.
6. После работы нажмите «Отключить» или закройте окно: прежние настройки прокси восстановятся,
   если другая программа/пользователь не успели их изменить.

Телефон может просто раздавать Wi-Fi или USB-интернет. RX-PRO на телефоне для этой
схемы не требуется. На ноутбук рекомендуется отдельный пользователь менеджера.

### Обновление с 0.1.0-rc1

Отключитесь и полностью закройте старое приложение. Распакуйте новый ZIP в отдельную папку
и запустите новый `RX-PRO Windows.exe` под той же учётной записью Windows. Профили остаются
в `%LOCALAPPDATA%\RX-PRO Windows` и подхватываются автоматически: удалять этот каталог,
перевыпускать S3-ключи или менять ссылки не нужно. Не запускайте RC и релиз одновременно.

### Границы первой версии

- **Прокси, не TUN/VPN всей Windows.** Игры, UDP и приложения, игнорирующие прокси,
  не покрываются. Такой трафик, системный DNS и фоновые службы могут идти напрямую.
  Kill switch и отсутствие всех DNS-утечек не заявляются. WinHTTP-службы и RAS/VPN-подключения
  со своими настройками прокси не перенастраиваются.
- Целевая клиентская система — **Windows 11 x64**. CI использует Windows Server 2022.
  Пользователь подтвердил успешную работу S3-клиента на реальном Windows-компьютере;
  точная версия ОС и тип подключения не зафиксированы. Это не полная проверка всех
  версий Windows 10/11 и вариантов мобильной раздачи. ARM64 и 32-bit не входят в выпуск.
- ZIP **не подписан Authenticode**. SmartScreen может показать предупреждение.
  Проверяйте происхождение и SHA256; отключать антивирус не нужно.
- **0.1.0 — обычный Windows-выпуск**, подготовленный после CI и успешного пользовательского
  теста RC. Транспорт, импорт ссылок и хранение профилей сохранены без функциональных изменений.
  Интерфейс пока базовый; его переработка не входит в этот выпуск. Отдельные замеры скорости,
  нагрузочные испытания и работа в БС не подтверждены.
- Bootstrap VK использует тот же явный IPv4-снимок, что Android 1.6.0: `95.163.53.117`.
  TLS Host/SNI и проверка сертификата сохраняются. При смене адреса нужен новый выпуск;
  скрытого внешнего DNS-fallback нет.
- Не запускайте одновременно другие программы, меняющие системный прокси. Управляемая
  политиками организации настройка может быть недоступна; используйте ручной режим.

### Профили и восстановление прокси

Профили сохраняются в `%LOCALAPPDATA%\RX-PRO Windows` с приватным ACL и **DPAPI текущего
пользователя**. Portable означает отсутствие установки, а не переносимость сохранённых
секретов между ПК. Чтобы перенести доступ, импортируйте ссылку заново. DPAPI не защищает
от вредоносной программы, уже работающей под вашей учётной записью. Буфер обмена также
содержит секрет: очищайте его после импорта. Не публикуйте ссылки/QR и файлы профилей.

Конфигурация с ключами передаётся ядру через stdin, не через argv и не через открытый JSON
на диске. Ядро проверяется по встроенному SHA256 и ограничено Windows Job Object.
Перед изменением WinINet записывается зашифрованный снимок прокси/PAC/WPAD. Отдельный
watchdog пытается восстановить его при аварийном завершении приложения; после перезагрузки
восстановление выполняется при следующем запуске RX-PRO. Изменения другого владельца не
перетираются. Если Windows блокирует восстановление, проверьте **Параметры → Сеть и Интернет →
Прокси** и верните известные прежние значения вручную. Не удаляйте журнал до восстановления.
Удаление профиля из приложения **не отзывает** доступ на сервере — для отзыва используйте менеджер.

### Проверки и сборка Windows

Windows job отдельно собирает закреплённый Xray/S3 на Go **1.27.1** и WPF-клиент на
.NET SDK **10.0.401**. Android-цели не запускаются. Проверяются строгий импорт, секретобезопасные
ошибки, настоящий DPAPI/ACL, WinINet и восстановление после сбоев, stdin/отмена/Job Object,
локальная TLS+SigV4 модель S3 с VLESS Encryption и запуск portable EXE. Это не тест живого VK.

```bash
python windows/build_core.py test
python windows/build_core.py windows
# Последующие команды выполняются на Windows:
dotnet run --project windows/RxPro.Tests -c Release -- .lab/windows-native/bin/xray-s3.exe
```

Системные тесты намеренно разрешены только на одноразовом GitHub runner. Не запускайте
их на личном ПК: тест меняет прокси и временно добавляет синтетический сертификат.
Полная сборка ZIP и лицензий описана в `.github/workflows/windows.yml`.

## Установка и обновление

Скачайте APK arm64-v8a из [Releases](https://github.com/cwash797-cmd/RX-PRO/releases), добавьте подписку и выберите профиль.

Версия 1.6.0 использует основной пакет `com.rixxx.rxpro` и ключ подписи RX-PRO. Она обновляет обычные RX-PRO 1.5.1, 1.5.4 и 1.5.5 без удаления приложения; миграция базы сохраняет профили. Перед обновлением рекомендуется резервная копия в безопасном месте. После перехода на новую схему базы откат на старый APK без восстановления резервной копии не поддерживается.

Если прежняя 1.5.2 была установлена отдельным приложением, её данные изолированы Android. Для перехода добавьте подписку в основном RX-PRO заново либо перенесите профили через экспорт/импорт. Не включайте VPN одновременно в двух клиентах.

## TrustTunnel

Поддерживаются официальный `tt://?<base64url TLV>` и человекочитаемый `tt://user:password@host:port?...`, включая обычные и Base64-подписки. Доступны редактор, QR/share, стандартный URL-тест задержки, Start/Stop.

Адаптер реализует TLS, отдельные hostname/SNI, client_random_prefix/mask, TCP CONNECT и UDP через `_udp2`. Используется существующий VPNService и защищённый upstream через sing-box; второй VPN не создаётся. Не нужны отдельный лаунчер, Termux, root или ручной SOCKS.

Границы поддержки:
- TrustTunnel доступен в arm64-сборке и использует HTTP/2. HTTP/3 и anti_dpi=true сохраняются при импорте, но запуск отклоняется. Client random prefix поддерживается независимо от anti_dpi.
- Используется первый/выбранный endpoint без автоматического переключения; остальные адреса сохраняются для экспорта.
- DNS для UDP-доменов внутри адаптера: IP или tcp://IP:port. DoH/DoT/DoQ в этом поле не поддерживаются. Настройки DNS самого RX-PRO действуют отдельно.
- ICMP relay через TrustTunnel не реализован. Для проверки туннеля используйте URL-тест, а не только ICMP/TCP ping.

## Изменения 1.6.0

- Перенесён проверенный на Android/VK и в БС S3-транспорт из S3 beta2: отдельное
  ядро Xray 26.9.30 с native SigV4 backend и обязательным VLESS Encryption.
- S3-ссылка импортируется как VLESS-S3. Работает с существующим S3 bridge и входом
  3x-ui; обычная VLESS-ссылка панели не содержит S3. [Настройка](docs/s3-start.md).
- Перед стартом VPN ожидается локальное SOCKS5-рукопожатие S3-ядра; Stop отменяет
  ожидание. Случайно вклеенные ссылки в названии скрываются при импорте/показе/экспорте.
- S3 работает в отдельном строгом режиме: пользовательские маршруты и DNS для него
  не применяются; chains, selector, custom JSON, per-app/LAN bypass отклоняются.
  Прикладной DoH идёт внутри туннеля, FakeDNS принимает только A/AAAA, не PTR.
- Bootstrap VK закреплён на IPv4 95.163.53.117 (проверен 2026-10-05), TLS Host/SNI
  и проверка сертификата сохранены. При смене IP VK нужен новый APK: внешнего
  DNS-fallback нет. Это не обещание отсутствия всего фонового трафика Android.
- Другие протоколы сохраняют свои ядра и обычные правила маршрутизации.
- Основной пакет `com.rixxx.rxpro`, versionCode 75. CI сравнивает сертификат с APK
  1.5.5 и запрещает выпуск при несовпадении. S3 beta остаётся отдельным приложением:
  её профиль нужно импортировать в основной RX-PRO, автоматического переноса нет.

Пользователь подтвердил первый реальный тест S3 beta2, включая БС; задержки и
скорость видео пока требуют дальнейшего измерения. Многоклиентская нагрузка и iOS
не считаются проверенными. Не меняйте работающий WS-вход ради S3.

## Изменения 1.5.5

- Исправлен импорт расширенных XHTTP-параметров из JSON-подписок: flattened transport, вложенный extra, перевод snake_case в Xray camelCase для padding, upload-настроек и xmux.
- Добавлено декодирование Base64/Base64URL extra из URI. Некорректный extra больше не отбрасывается молча. Явные mode=auto и path=/ не заменяются значениями из extra.
- Исправлен импорт XHTTP из контейнера Xray outbounds и отдельного sing-box outbound, сохранены TLS/REALITY-параметры; tls.enabled=false теперь учитывается.
- Старые ссылки правил geosite:ru загружают существующую category-ru, сохраняя теги DNS/маршрутизации. В сборке проверяется наличие непустых категорий geosite для пресетов.
- Удалены штатные пресеты Китая/Ирана, Play Store переименован в «для RU» без изменения googleapis.cn и действия маршрута. Миграция распознаёт полные исходные пресеты; переименованные или изменённые пользователем правила не удаляются.
- Экспорт журнала явно отмечает пустой журнал ядра и объясняет, как включить диагностику.
- Добавлены регрессионные тесты XHTTP и маршрутов. Версии sing-box/Xray/Naive/Mieru не менялись; второй VPN не создаётся, TLS-проверка не отключается.

Раздельный XHTTP downloadSettings сохраняется при импорте/экспорте, но запуск отклоняется: отдельный download endpoint требует собственного защищённого mapping. Прямое соединение в обход существующего VPN lifecycle не допускается.

После обновления **обновите подписку либо повторно импортируйте исходную XHTTP-ссылку**: параметры, потерянные при старом импорте, нельзя восстановить из сохранённого профиля.

Исправления проверяются на синтетических профилях и локальном Xray-стенде. Лог Redmi с отключённым журналированием не содержал ошибок Xray, поэтому исправление именно этого сетевого случая не подтверждено. Если сбой сохраняется, включите журналирование, перезапустите приложение и повторите URL-тест; перед передачей отчёта проверьте его на приватные данные.

### О Hysteria2

Ошибка `timeout: no recent network activity` означает, что QUIC не получил ожидаемой активности вовремя. Она сама по себе не доказывает неверный пароль или ошибку импорта. Возможны недоступность сервера, фильтрация UDP, неверная серверная конфигурация или особенности сетевого маршрута. `context canceled` после Stop/смены профиля отражает отмену операции.

В 1.5.4 нет заявления об исправлении сетевой доступности Hy2: порт, пароль, SNI и TLS-параметры в рассмотренном случае переносились из URI корректно. Проверка сертификата не отключается для обхода таймаутов.

## Диагностика и безопасность

Ссылки и экспорт профилей содержат пароли. Старые диагностические журналы могли содержать ссылки и полные конфигурации. Не публикуйте их; при раскрытии смените credentials. Новые журналы по-прежнему могут содержать адреса и домены сетевых подключений и требуют проверки перед передачей третьим лицам. Полная анонимность журналов и отсутствие DNS-утечек не заявляются.

## Сборка

Требуются Java 17, Go 1.25.0, Android API 35 / Build Tools 35.0.0 и NDK 27.0.12077973.

```bash
./run lib core
bash trusttunnel-core/build-android.sh
bash buildScript/lib/plugins.sh
bash buildScript/lib/assets.sh
# S3 targets require Go 1.27.1 (set GO to its binary):
python3 s3-core/build.py test
python3 s3-core/build.py android
(cd trusttunnel-core && go test -race ./...)
./gradlew :app:testOssDebugUnitTest :app:assembleOssRelease
```

Подпись настраивается через KEYSTORE_PASS, ALIAS_NAME, ALIAS_PASS либо LOCAL_PROPERTIES. Секреты не хранить в исходниках. Публикуется arm64 APK с проверенной подписью и SHA256. GitHub Actions: Android arm64 Build; Release Build публикует только при явно включённом параметре publish и не перезаписывает существующие релизы.
